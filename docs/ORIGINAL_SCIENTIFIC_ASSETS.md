# Original scientific visual evidence

`daily_agent.paper_visual_assets` extracts a bounded set of **original PDF
crops**, never generated illustrations, chart reconstructions or guessed LaTeX.
It does not change reading completeness, claim verification, quality approval,
delivery confirmation or replication status.

## Preparation contract

`write_reading_notes` invokes `prepare_report_visuals` before rendering or seal.
Enable `report_writing.paper_visual_assets_enabled: true`; choose
`paper_visual_selection_provider: parent_queue` only in parent-assisted workflows.
The wrapper catches unavailable sources as gaps while propagating queue pending
states. An already-reviewed selection is reused without a new model request.

1. Keep the reading document's `source_pdf_path` and `source_pdf_sha256` intact
   (or its `native_document` when reviewed transcription is in use).
2. Before report sealing, call `request_visual_selection(material, root)` when
   parent-assisted selection is enabled. This uses the existing parent queue,
   passes at most eight candidate page images, and propagates PendingResponse so
   the workflow can resume. It needs no paid API or new key. Candidate pages
   come from existing visual-reading notes and are balanced across formula,
   figure and table nominations. If there are no candidates, it records an
   explicit empty selection, not a fabricated success.
3. A selector must inspect actual supplied pixels, use original page-point
   coordinates, retain labels/legends/units/table headings and relevant caption,
   and state conditions. Choose at most five useful items: an actual framework
   when present, key result figures/tables, and core equations when present.
   For uncertain LaTeX use the original equation crop. If a paper only describes
   an objective in prose, identify an `objective_excerpt`, not an equation.
4. Store the returned object in `material.raw['paper_visual_selection']`; call
   `prepare_visual_assets(material, reports_dir, settings)` before rendering.
   `paper_visual_assets_enabled: true` exposes an honest missing-selection gap;
   it does not silently claim an image was inspected or queue paid work.
5. Render `visual_assets_html(material)` or consume `verified_assets(material)`
   for an archive. The former embeds only validated PNGs; the latter returns
   validated `(asset_record, png_bytes)` pairs. An archive can externalize these
   bytes under content-addressed names. Do not expose private internal paths.

## Selection JSON

```json
{
  "schema_version": 1,
  "source_pdf_sha256": "SHA256_OF_EXACT_READING_PDF",
  "assets": [{
    "kind": "result_table",
    "number": "Table 2",
    "page": 7,
    "bbox": [303, 64, 547, 340],
    "page_image_sha256": "SHA256_OF_PAGE_REVIEW_IMAGE",
    "caption": "Short Chinese explanation, faithful to the actual original",
    "conditions": "Units, dataset, comparison, assumptions and author-reported status",
    "review": {"labels_checked": true, "conditions_checked": true}
  }],
  "gaps": ["Explain absent framework/equations or unavailable/paywalled evidence"]
}
```

The source PNG reviewed by the selector is generated by `page_review_image`
at 1.5 pixels per PDF point. Crops are rasterized at 2 pixels per point. The
allowed kinds are `framework`, `result_figure`, `result_table`, `equation`, and
`objective_excerpt`. Review flags record selector assertions, not independent
scientific approval. Hash checks establish byte identity, not truth.

The runtime enforces five crops and 2,000,000 PNG bytes per paper. Invalid,
nonfinite, reversed, out-of-bounds or duplicate coordinates fail closed. Missing
PDFs, missing reading identity, changed reviewed pages, changed selections,
changed captions/provenance and changed PNGs suppress the images. State
`status` is `ready`, `empty`, `unavailable` or `invalid`; there is no visual
claim-verification `PASS`. Every figure visibly discloses page, crop range,
source PDF SHA-256 and crop PNG SHA-256. The sanitized manifest keeps no private
filesystem path. Generated HTML escapes text, removes private local paths,
and suppresses non-web, credential-bearing, localhost/private-IP source links.

## Experimental-plot coverage policy v2

The initial five-slot calibration overselected tables and omitted available
experimental plots. This was an editorial omission, not an extraction failure.
New parent-assisted selections now carry `selection_policy_version: 2` and
`experiment_plot_coverage` with `reviewed`, `available`, `key_plot_numbers`, and
an explicit `omission_reason`/`absence_reason` when appropriate.

Experimental plots and tables are separate evidence categories. Inspect and
prioritize overall-comparison, ablation, learning/convergence, scaling and
robustness plots. Include at least one relevant key experimental plot if present,
or disclose a specific reviewed reason for omission. Prefer complementary
experimental plots before redundant tables; objective prose stays outside the
visual crop budget. No experimental plot is forced for a theory-only or otherwise
nonapplicable paper. A missing candidate-page inventory means **unknown**, not
an affirmative claim that no plot exists, and never fabricates pixel review.

A dedicated plot-page nomination queue prevents numerous framework pages from
exhausting the eight-page inspection budget. The changed prompt and policy
version alter the parent queue identity. During preparation of a new, unsealed
report with parent selection enabled, a legacy policy selection is refreshed
once; a current unchanged selection is reused. Historical sealed artifacts are
not rewritten and can still be rendered with their original explicit selection.

`selection.json`. It selects Figure 7, Figure 1, Figure 2, Table 3 and Table 4.
The five PNGs total 351,811 bytes. Fig1 preserves different LIBERO/LIBERO-plus
